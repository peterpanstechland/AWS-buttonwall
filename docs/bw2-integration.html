BW2 固件与 RDK 联调

基线：Git c1c8f2d 的 USB 线束测试；保留 GPIO、驱动字节顺序、原生 USB 和测试入口。修复 100 Hz FreeRTOS 下 1 ms 延时为零导致 IDLE0 饥饿，以及灯任务只有 taskYIELD 无法让出低优先级任务的问题。看门狗保持开启。

传输契约

ASCII 行协议，换行结尾，最多 255 字节。所有整数为十进制；映射 CRC 来自 config/hardware.json，与 generated_hw.h 同源。主机握手前禁止输入游戏；按住开机须先全部松开。

命令／响应意义
BW GAME 2 crc进入游戏模式，CRC 不符拒绝。
BW HELLO 2 boot crc uptime_us mask握手回应，bit 0 为 Kiro，bit 1–16 为服务 ID。
BW STATE boot seq uptime_us mask每次去抖边沿和每 100 ms 发送；序列须连续，重启／丢包立即中断体验。
BW FRAME seq hex完整 16 面板场景：128 个十六进制字符，每面板 R,G,B,effect 共 4 字节。effect 0 关、1 常亮、2 闪动、3 呼吸。先完整验证再应用。
BW FRAME_OK seq lamp_ready场景已交给驱动，lamp_ready 表示按钮灯初始化成功；不是光学反馈验收。
BW KEEP主机每 500 ms 发送；固件 2 秒无命令熄灯退回测试模式。
BW PING / BW SLOT A1 / BW OFF保留线束测试。游戏模式拒绝 SLOT，OFF 可退出并熄灯。

RDK 配置

DEVICE_MODE=bw_serial
WALL_SERIAL_PORT=/dev/serial/by-id/usb-Espressif_USB_JTAG_serial_debug_unit_84:C7:BB:79:BF:94-if00

将配置写入 /etc/aws-wall.env；服务用户须具有 dialout 组权限，再重启 wall-backend。端口按当前实际设备选择，不能只依赖可能变化的 ttyACM 序号。旧固件未刷写前保留 DEVICE_MODE=mock。

刷写与回滚

固件构建使用 ESP-IDF 5.4.1。发放包包含 app、bootloader、partition table 及构建生成的 flasher_args.json。刷写前读取并保留目标设备原 Flash；确认芯片为 ESP32-S3、Flash 为 16 MB，按 flasher_args.json 的偏移与模式刷写，不从 sdkconfig.defaults 猜测模式。本机现有构建实际为 DIO。昨日构建的 app 二进制另有本地备份；这不等同目标设备完整 Flash 备份。

验证范围

ESP32 编译和分区大小检查；主机协议测试包含 CRC、旧协议拒绝、分包、重复序列、短按、Kiro 手势、开机按住、断线和灯效确认；RDK Linux PTY 端到端测试覆盖实体输入进入自由探索并选择 Lambda。尚需真实刷写后的 16 格位置／颜色、Kiro、同时按键、USB 插拔和长时间运行验收。

正式排名仍关闭：BW2 是主机计时的实体体验桥接，不能代替 AWG1 MCU 时间戳、可靠重传与比赛结算完整性协议。
