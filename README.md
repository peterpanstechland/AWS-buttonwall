## 本地玩一局

```bash
python3 -m unittest discover -s tests -v
python3 -m wall_backend
```

浏览器打开 `http://127.0.0.1:8091/`。这台机器的 `8080` 已被 Open WebUI 占用，所以游戏默认用 `8091`，可用环境变量 `WALL_PORT` 改。默认是模拟器，顶栏会标 `DEMO`，模拟出来的竞速成绩不进正式榜。

维护口令用环境变量 `WALL_OPERATOR_PIN`。RDK 上的 systemd 和 udev 样例在 `deploy/`，VID/PID 还要按实机改，不能直接当生产配置。

## 构建界面与垮塌规则（2026-10-14）

HMI 进入构建场景后，以业务入口、能力节点、分支连线和业务输出组成架构画布。
实体按键经过后端判定后点亮对应的角色实例；连线两端及其必要上游均接通后，数据流才开始流动。
M07 的两只 Lambda 分别代表入队和消费角色，不会因同一实体键亮起而一起完成。
CloudWatch、Cognito 等辅助关系独立显示。正常界面使用一个 Kiro 玩法控件和顶栏语言切换，不复制实体服务按键阵列。

按本次玩法要求，引导与竞速启用三个垮塌条件：拍错服务、单步超过 10 秒、整局 60 秒结束且当前架构未完成。
配置在 `config/game_config.json` 的 `collapse` 中；单步限时可调整或设为 0 关闭。
自由构建允许试选、撤销和添加实例，不对探索中的未完成组合判错；分析后可查看不同候选架构。
引导暂停冻结单步计时，可选角色不延长单步预算。整局超时仍先等待 MCU 的输入排空屏障，截止前的有效按击不会被动画丢弃。

垮塌终止本局，保留此前完成数、得分和既有错误扣分。它属于有效游戏结果（`final_state=VALID`），
由快照中的 `failure` 和 `graph.status=collapsed` 区分；设备故障仍为 `INTERRUPTED`。
新规则标记为 `rules-v1.3-collapse`，垮塌参数参与赛题包 hash，与旧规则榜单隔离。模拟器永远不进入正式榜。
这些变更覆盖 V1.2 规格中“拍错后可继续”等旧行为，原有计分分值和 MCU 帧格式保持兼容。

`config/solutions.json` 是角色与激活依赖；`config/workflows.json` 是可编辑的教学能力流、坐标和连线标签。
图中箭头表示能力交接，不表示实际部署的 AWS 网络拓扑；返回路径被简化，标有 ¹ 的结果交接由业务编排负责。
图标随 HMI 本地打包，来源与 SHA-256 记录在 `hmi/icons/manifest.json`。无官方本地图标的 EC2、IoT 使用文字标记。
界面无远程字体、CDN 或云请求，支持中英文、暂停流动和减少动态效果。

## 7–10 寸横屏与 Kiro 交互

视觉主题对应活动的 [Bridge with Signal / Signal Hunt](https://2026-autumn-events.awscommunityday.cn/signal_hunt.html)：
明黄 `#ffd900`、米白 `#fff9e3`、黑 `#141414`、蓝 `#2b5ce6`、紫 `#6c3fd4`。
`hmi/signal.css` 管理活动配色；入口桥梁为本地 SVG，shader 负责信号波、节点脉冲与链路粒子。
按钮墙作为“架构构建站”，用服务能力构成信号桥；图中数量与结果仅属于本局架构。
活动网页的 8 个 NFC 打卡点仍由活动系统管理，这里尚未接入 NFC 打卡、领取或完成状态。
固定顶栏使用用户提供的亚马逊云科技深色 logo 和 Kiro SVG；Kiro 主控键也使用原始图标。
品牌素材保存在 `hmi/branding/`，原文件校验记录在该目录的 `manifest.json`。
PNG 自带上下透明留白，仅通过 CSS 取景显示实际标志，保留原始像素、比例和颜色；浅色版本一并保留。

主布局按 1280×800 横屏设计：架构占据画面主体，底部显示下一项能力、单步倒计时和 Kiro 操作提示。
待机页将唯一的 Kiro 控件放在主视觉标题下方，显示为 400×112 的“开始构建”按钮；开始后同一控件回到底部，保留原有手势。
界面不依赖触屏，实体服务键负责选择能力，Kiro 负责导航。当前手势约定：

- 待机：单击进入；模式／场景选择：单击切换，双击确认，长按 2 秒返回。
- 引导：单击暂停／继续，长按返回模式。成功后单击下一关；失败后单击重试；双击回模式；长按回待机。
- 竞速：长按提出结束，双击确认、单击取消；确认期间比赛时钟继续。
- 自由编辑：单击分析，双击撤销上一次服务操作，长按返回模式。
- 自由分析：单击切换候选，双击确认完整方案，长按继续编辑；拍服务键也会返回编辑。
- 自由构建中重复拍 Lambda 按实例数循环 `0 → 1 → 2 → 0`，无需额外增加实例按钮。

本机用空格／回车或屏幕 Kiro 模拟按下和松开，由虚拟 MCU 的去抖及手势分类器判定。
鼠标输入为每个电平保留至少 45ms，保证快速点击仍经过 20ms 去抖；双击窗口为 300ms，长按为 2 秒。
右上角常驻 `中文 / EN`，点击切换整套界面语言，当前语言以下划线标示；选择保存在本机浏览器，刷新后保留。
构建中切换语言只更新文案，不重置进度、得分或计时。用 Tab 聚焦语言按钮后，空格／回车仅切换语言，不触发 Kiro。
用 `http://127.0.0.1:8091/?debug=1` 显示减少动效和服务输入抽屉；演示时也可按反引号打开抽屉。

`hmi/energy-field.js` 是本地 WebGL 1 shader：环境能量场、沿实际 SVG 曲线的流动粒子、节点光晕与激活波纹。
失败时粒子散落、节点倾斜下坠、链路熄灭。渲染最多 30fps，画布像素预算 70 万，限制点粒子尺寸；后台、暂停和减少动态效果时停止连续重绘。
无需额外 Three.js/p5.js 运行库；SVG 保留清晰文字与可访问结构，WebGL 不可用或上下文丢失时自动回退，恢复时重新创建资源。
可用 `?effects=off` 强制检查 SVG 路径。动态效果只反映后端状态，不参与玩法判定。

自动化测试覆盖三类垮塌、时间边界、重复角色、并行依赖、榜单隔离、九个场景的完成路径及 Kiro 电平手势导航。
本机浏览器验证不能替代 RDK X5 实测；板上 Chromium 帧率、串口及灯带联动仍需验证。

## 固件

ESP-IDF 5.4.4，目标 `esp32s3`。

```bash
. ~/esp/v5.4/esp-idf/export.sh
python3 tools/gen_hw_header.py
cd firmware
idf.py set-target esp32s3
idf.py build
```

当前固件做开机全灭、17 键去抖、四路 WS2815，并在日志串口上听逐口测试命令。USB CDC 还没接上原生 OTG，日志走 UART，不进灯带数据线。

## 逐口测试

只有一套按键、灯带和按钮灯时，用电脑逐个插 16 个口。页面是观众视角的 4×4，和 `config/hardware.json` 的 `display_grid` 一致。引脚用这份 v0.8 网表，不沿用旧文档。

```bash
python3 tools/port_test.py
```

用 Chrome 或 Edge 打开弹出的页面，连接开发板上 CH340 那个 USB，波特率 115200。点一个口：该组灯带前 32 颗跑马，这一口的按钮灯亮，页面提示按下按键。收到对应口才算通过；收到别的口会标出实际接到了哪里。

换插头前先关 12V。A2、B2、C2、D2 以及同组更后面的口，灯带数据从上一口的 DOUT 进来，原理图没有旁路跳帽。测这些口的灯带时，先断电把前面每个口的第 5 脚和第 7 脚短接。按键和按钮灯不经过这串数据。

固件要先烧录上面的 ESP-IDF 工程。串口命令是 `BW PING`、`BW SLOT A1`、`BW OFF`，应答以 `BW ` 开头。
